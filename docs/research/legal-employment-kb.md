# 中国劳动用工与劳务派遣法律知识库研究

> 核验日期：2026-08-21  
> 范围：中国大陆全国性规则；地方规则须按实际用工地另行叠加。  
> 用途：为 Forge 建设可追溯、可按时间和地域过滤的法律知识库。本文件不是法律意见，正式合同、裁员、派遣、工伤及争议处理仍应由执业律师复核。

## 结论

不要把若干 PDF 直接切块后全部放进同一个向量库。法律知识库至少要有两层：PostgreSQL 保存法规、版本、条款、效力和变更关系的权威记录；Milvus 只保存可检索的条款切片及其过滤字段。回答时先按“查询日期 + 适用地域 + 效力状态”做硬过滤，再进行关键词/向量召回。

“用工合同”不是一个可以统一套用的法律概念。入库和问答前应区分：劳动合同、劳务派遣单位与劳动者的劳动合同、劳务派遣协议、超龄劳动者书面用工协议、民事劳务/承揽协议、业务外包。名称不是唯一判断标准，应保存实际管理、报酬、工作内容等适用事实。2026 年 7 月 1 日生效的《超龄劳动者基本权益保障暂行规定》尤其要求用人单位与适用的超龄劳动者订立书面用工协议，是本库截至核验日必须纳入的新规则。[人社部所属中国人力资源市场网发布说明](https://chrm.mohrss.gov.cn/%E4%BA%BA%E5%8A%9B%E8%B5%84%E6%BA%90%E7%A4%BE%E4%BC%9A%E4%BF%9D%E9%9A%9C%E9%83%A8%E7%AD%895%E9%83%A8%E9%97%A8%E8%81%94%E5%90%88%E5%87%BA%E5%8F%B0%E3%80%8A%E8%B6%85%E9%BE%84%E5%8A%B3%E5%8A%A8%E8%80%85/)

## 法规层级和冲突处理

《立法法》明确：宪法效力最高；法律高于行政法规、地方性法规和规章；行政法规高于地方性法规和规章；同一机关制定的规范，特别规定优于一般规定、新规定优于旧规定。部门规章与地方政府规章之间并非简单按“中央优先”，冲突可能需要法定机关裁决。因此系统可以给出 `authority_rank` 帮助检索，但不能让一个整数自动裁决所有冲突。[《中华人民共和国立法法》第九十八条至第一百零六条](https://www.npc.gov.cn/npc/c2/kgfb/202303/t20230314_424438.html)

建议分层：

1. 法律及全国人大常委会有关法律问题的决定；
2. 行政法规；
3. 最高人民法院司法解释；
4. 部门规章；
5. 地方性法规、地方政府规章；
6. 行政规范性文件；
7. 官方解释、答复、指导性/典型案例（解释材料，不与法条混为同一效力）；
8. 草案、征求意见稿（只用于变更预警，绝不能作为现行法回答）。

公报文本应优先作为标准文本。《立法法》规定，国务院公报刊登的行政法规文本以及国务院公报、部门公报刊登的规章文本为标准文本；地方人大常委会公报和地方政府公报也分别承担标准文本作用。[《立法法》第七十九、八十九、九十七条](https://www.npc.gov.cn/npc/c2/kgfb/202303/t20230314_424438.html)

## 数据模型

### 法规主表 `legal_instrument`

- `instrument_id`：内部稳定 UUID；
- `canonical_title`、`aliases`；
- `document_number`：主席令、国务院令、人社部令、法释编号等；
- `instrument_type`：法律、决定、行政法规、司法解释、部门规章、地方性法规、地方政府规章、规范性文件、案例、解读、草案；
- `issuing_authorities`；
- `jurisdiction_country/province/city/district`；
- `subject_tags`：派遣、劳动合同、工资、工时、社保、工伤、超龄用工等；
- `promulgated_at`、`effective_from`、`effective_to`；
- `status`：`draft`、`not_yet_effective`、`effective`、`partially_amended`、`repealed`、`expired`、`unknown_pending_review`；
- `official_url`、`official_file_url`、`gazette_issue`；
- `source_retrieved_at`、`raw_sha256`、`parser_version`；
- `review_status`、`reviewed_by`、`reviewed_at`。

主键不能只用标题。建议自然唯一键为“制定机关 + 文号 + 公布日期”，无文号文件再使用官方页面 ID 和正文哈希。

### 不可变版本表 `legal_version`

- `version_id`、`instrument_id`、`version_no`；
- `valid_from`、`valid_to`、`version_status`；
- `event_type`：制定、修正、修订、解释、废止、失效；
- `event_document_id`；
- `supersedes_version_id`；
- `full_text`、`raw_snapshot_uri`、`content_sha256`；
- `change_summary`、`human_verified`。

不要覆盖旧文本。比如解释（二）只明确废止解释（一）第三十二条第一款，因此需要条款级关系，而不是把解释（一）整篇标成废止。

### 条款表 `legal_provision`

- `provision_id`、`version_id`；
- `chapter_no/title`、`article_no`、`paragraph_no/item_no`；
- `text`；
- `effective_from/effective_to`；
- `provision_status`；
- `amends/repeals/replaces/interprets` 关系；
- `applies_to_entity`、`applies_to_worker`、`employment_model`、`jurisdiction`。

Milvus 中每个向量对应一个条或一个自然款，metadata 至少冗余：`instrument_id`、`version_id`、`article_no`、`instrument_type`、`jurisdiction`、`effective_from`、`effective_to`、`status`、`official_url`、`content_sha256`。Forge 当前 `ruibo_knowledge_v2` 只有 `published_at`、`validity_status`、地区和通用文章字段，不足以表达法律沿革、条款级部分失效和适用日期；建议新建法律专用 collection，并由 PostgreSQL 做事实主库，不要在现有 collection 上做兼容性补丁。

## 更新、审核和发布机制

1. **发现**：每日抓取各 P0/P1 列表页，仅把新增 URL、文号、状态变化和内容哈希变化生成 `change_candidate`。
2. **取证**：下载官方 HTML 与官方 PDF/公报原版；记录获取时间、来源 URL、HTTP 元数据和 SHA-256，原始文件只追加不覆盖。
3. **解析与比对**：按章、条、款解析；与上一版本做条款级 diff；识别“修改、废止、失效、施行”文件中的目标条款。标题相同但哈希变化不自动发布。
4. **自动校验**：校验制定机关、文号、公布日、施行日、效力状态；至少两个官方入口交叉核验高风险变更。若两个官方来源冲突，状态置为 `unknown_pending_review`。
5. **HITL 法律审核**：审核员看到原版、结构化字段和 diff，明确批准版本关系、条款失效范围、适用地域和生效日期后，才能进入生产索引。
6. **原子发布**：先提交 PostgreSQL 新版本，再写入新的 Milvus 分区/别名；全部成功后切换 `active_version`。失败时仍由旧的已审核版本服务。
7. **告警**：草案发布、正式公布、距施行 30/7/1 天、状态由有效转已修改/废止、抓取失败连续两次、官方页面无预期字段时分别告警。草案转正式文件必须新建正式记录并关联，不能原位改状态后继续沿用草案文本。
8. **周期核对**：每日增量、每周按主题词全量核验、每月由法律负责人抽查，季度生成“现行/部分失效/待复核/抓取失败”清单。

主题词不应只有文件名，应覆盖：`劳动合同`、`劳务派遣`、`用工协议`、`劳务外包`、`劳动关系`、`工资`、`最低工资`、`工作时间`、`休息休假`、`社会保险`、`工伤`、`竞业限制`、`经济补偿`、`超龄劳动者`、`退休`、`劳动争议`、`个人信息`，并监测“修改、修订、废止、失效、决定、解释、批复、征求意见”等动作词。

## 检索与回答门禁

- 查询必须带 `as_of_date`；默认当天，但答案要显示该日期。
- 涉及工资、休假、社保、工伤或地方派遣政策时必须有实际用工地；没有就先追问。
- 生产回答只检索 `effective` 或在查询日期有效的条款；`draft`、`not_yet_effective` 和 `repealed` 默认排除。
- 先做法规层级、日期、地域和主体过滤，再做 BM25/关键词与向量混合排序；法规名称、文号、条号宜提高精确匹配权重。
- 每个法律结论都回传：法规全名、版本、条号、效力状态、施行日期、官方链接、知识库最后核验时间。
- 若旧法适用于历史事实，应按事件发生日期检索旧版本，不能总是返回最新版。
- 对合同模板输出设置第二道人工审批；知识库可以提示风险和引用依据，但不应自动声称合同“完全合法”。

## 推荐落地顺序

第一阶段只做全国性核心 12—20 部文件、条款级切分、版本表和人工审核后台；用一组固定问题验证派遣三性、10% 比例、同工同酬、派遣许可、二倍工资、社保、竞业限制和超龄用工。第二阶段选择业务最常发生的一个省和一个市，建立地方规则叠加与地域门禁。第三阶段再接入草案监控、自动条款 diff 和通知。

上线验收至少包含以下时态测试：2025-08-31 与 2025-09-01 查询解释（一）第三十二条第一款得到不同结果；2026-06-30 与 2026-07-01 查询超龄用工协议得到不同结果；查询某市最低工资时不得引用另一城市标准；草案不得进入现行法答案；官方来源冲突时必须返回“待人工核验”。
