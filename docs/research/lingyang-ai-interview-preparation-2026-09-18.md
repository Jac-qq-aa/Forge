## 1. 业务资料与岗位关联

### 1.0 先看业务全貌，不只押Quick BI

瓴羊官网产品矩阵包含AgentOne、Quick BI、Quick Audience、Quick Service和Dataphin。AgentOne公开定位为企业级Agent平台，营销场景涉及内容批量生产、多平台分发及效果复盘，与Forge有直接交集。Quick Audience公开介绍创意、策划、素材、投放和结案分析类Agent。

来源：[瓴羊官网](https://www.lydaas.com/)、[AgentOne](https://ai.lydaas.com/)、[Quick Audience](https://www.lydaas.com/quickaudience)。这是产品公开定位，不代表此次岗位一定属于某产品线。

准备分支：营销方向讲品牌与事实约束、内容版本、发布授权与效果评估；问数方向讲SQL、业务口径与权限；客服方向讲RAG、工单、转人工和操作幂等。共同基础是任务状态、工具执行、评估和可靠性。

### 1.1 智能小Q：准备的不只是聊天问答

Quick BI 官方将智能小Q定位为数据分析助手，能力涉及自然语言问数、数据解读、报告和看板搭建。不同文档页的 Agent 数量存在版本差异，面试不必背固定数量。

来源：[智能小Q概述](https://help.aliyun.com/zh/quick-bi/user-guide/smartq)、[操作指南](https://help.aliyun.com/zh/quick-bi/user-guide/smart-q-home-page)。

准备关联：意图路由、工具调用、结构化数据查询、生成可靠性和多轮交互。应先向面试官确认岗位偏数据分析、企业知识应用、营销客服还是底层平台。

### 1.2 问数准确性依赖业务语义

官方入门教程提供了两个有价值的例子：模型选择的销售利润率计算公式不符合业务预期；“中国区”对应的数据筛选维度存在歧义。教程通过计算字段和业务知识配置修正。

来源：[轻松上手智能小Q](https://help.aliyun.com/zh/quick-bi/getting-started/smartq-novice-guide)。

面试理解：SQL 能运行不意味着业务答案正确。需要关注指标定义、时间范围、统计粒度、实体同义词和澄清机制，不应将全部问题归因于模型能力。

### 1.3 小Q报告与你的长文本项目相关

官方文档描述了从分析计划、数据获取到报告编写的流程，也支持后续编辑。报告编辑器可以查看引用资源及创建过程。这里可将 Forge 的事实清单、章节生成和人工确认经验迁移到“数据支持的报告”，但不要声称已经做过 BI 报告系统。

来源：[小Q报告概述](https://help.aliyun.com/zh/quick-bi/user-guide/intelligent-data-reporting/)、[报告编辑](https://help.aliyun.com/zh/quick-bi/user-guide/document-editing)。

### 1.4 企业权限是关键区别

Quick BI 的问数配置涉及授权；报告可根据查看者的行列权限重新取数。生成能力必须与已有权限体系结合。

来源：[数据准备](https://help.aliyun.com/zh/quick-bi/user-guide/prepare-data)、[小Q报告管理](https://help.aliyun.com/zh/quick-bi/user-guide/intelligent-data-reporting-management)。

准备关联：工具执行层鉴权、跨租户隔离、缓存权限边界、日志敏感数据、导出和静态文本泄露。权限不能只写在提示词里。上述内容是设计练习，不是官方内部架构说明。

### 2.3 项目三分钟结构

1. 业务：谁使用，输入是什么，最终交付什么；不把导出文本说成已全自动发布。
2. 基线：直接生成遇到哪些可复现问题。
3. 方案：事实收集与确认、章节规划、生成、核验、局部修改、人工定稿。
4. 代价：分段可能损害连贯性，抽取可能漏检，同模型评审可能有共同偏差。
5. 评估：只讲最可靠的两组实验，说明样本、分母、基线和限制。
6. 边界：已实现什么，后续准备改什么。

## 3. 重点题与回答骨架

### Q1. 如何设计一个企业问数Agent？

以下是设计建议，不是瓴羊已公开的内部架构：

用户身份与权限 → 问题解析 → 歧义澄清 → 指标/表结构/业务口径检索 → 查询计划 → SQL生成 → 程序化校验与权限检查 → 受限执行 → 结果校验 → 图表与解释 → 来源和执行轨迹。

- 先确认指标、时间、粒度和可访问范围，不确定时问用户。
- 查询服务使用受限账号；查询结构校验、超时和资源限制不能只依赖提示词。
- 只读也可能引起超大扫描、昂贵函数或数据泄露，需要额外控制。
- 用可信计算产生数字，模型组织解释；无证据时不编造原因。
- SQL报错可进行有限修复；越权不通过修改提示词重试绕过。
- 准确率同时看业务口径和执行结果，不只看SQL是否成功或字符串是否完全一致。

练习题：“上个月华东销售为什么下降？”先问销售指什么、是否排除退款、比较环比还是同比，再考虑地区/产品/渠道拆解。分组贡献可以提示解释方向，不能自动证明因果。

### Q2. RAG召回不好怎么排查？

固定失败问题和预期证据，逐层排查：语料是否存在且有效 → 解析是否完整 → 切片是否破坏语义 → 查询改写是否偏题 → 召回是否命中 → 重排是否丢掉证据 → 上下文是否被截断 → 生成是否忠实。

企业名、型号、编号可考虑关键词检索；语义变化可考虑向量检索；融合后重排。不能一遇到问题就增大top-k。

阿里云百炼公开提供Query改写、向量与关键词混合检索以及重排能力，可作为相关生态学习资料，不能据此假设瓴羊该岗位内部必用百炼。[知识检索](https://help.aliyun.com/zh/model-studio/rag-knowledge-retrieval)

### Q3. 没有完整事实清单怎么办？

先承认无法再以清单覆盖率保证完整性。可从生成稿抽取可核验陈述，为每项查找直接证据，区分支持、冲突和证据不足；无法核实则限定表述、删除或人工处理。这个流程能检查已写内容，不自动保证没有遗漏重要信息。

### Q4. Critic为什么独立，怎么判断修改有效？

拆分的价值是职责清晰、输入输出受控、方便单独评估；不是“两个Agent必然更可靠”。追踪问题ID、严重度、证据和所在段落，对比修复与新增错误。最大轮数只是底线，还可设置停滞、质量退步、耗时和成本预算。新增机制若未实现，应明确是改进方案。

### Q5. LangGraph暂停恢复如何避免重复执行？

要讲状态、节点、边、合并规则、检查点、会话标识和恢复输入。不要称为只能表示DAG。官方interrupt说明：恢复时节点从头执行，而不是普通程序断点逐行续跑。因此节点内外部写操作需考虑幂等和去重，恢复接口也需鉴权。

来源：[LangGraph interrupt参考](https://reference.langchain.com/python/langgraph/types/interrupt)。具体行为以项目实际依赖版本验证。

### Q6. 100个用户同时生成报告怎么办？

先确认吞吐、延迟和模型配额目标，再设计：接入层创建任务并快速返回；后台执行；按租户/模型限制并发；排队与拒绝策略；超时取消；有限重试；任务状态持久化；进度推送；结果与失败原因查询。重试要区分暂时故障与永久错误，外部副作用要幂等。

不能说“async就能无限并发”。Python官方文档说明了协程任务、gather和TaskGroup的不同异常传播行为，以及将阻塞I/O移出事件循环的方法。[Python asyncio任务文档](https://docs.python.org/3/library/asyncio-task.html)。TaskGroup自3.11提供，面试按所用版本说明。

### Q7. 如何评估AI应用？

- 检索层：Hit@k、Recall@k等，说明相关文档标注和查询集。
- 事实层：错误检出、误报、遗漏和新增错误；程序规则、人工与模型评审各有边界。
- 任务层：完成率、人工修改量、采用率。
- 系统层：延迟分位数、成本、失败率、恢复率。
- 人工偏好：同一任务同一素材，隐藏来源、随机顺序、允许平局，记录评价分歧。

每个指标都要有固定测试集、基线、版本及失败样例；不要把模型评分当事实真值。

### Q8. 路由选错但还能回答怎么办？

以自己的真实案例回答：曾发现系统有输出却一直走普通问答。只检查有无答案会遗漏这类静默失败。应检查预期工具调用、检索命中和来源；需要私有知识却没有取到证据时不能直接用通用回答冒充成功。必须补出真实根因和回归结果，尚未查清就不要编造。

### Q9. Workflow与自主Agent怎么选择？

依赖明确、风险较高、便于验收的步骤采用可控流程；探索型任务可给予模型一定工具选择空间，但限定权限、预算和退出条件。不要回答“模型强了所以删除校验”，应说哪些固定规则仍由程序保证、哪些规划可交给模型，并通过评估对比。

### Q10. 企业数据安全如何做？

身份和资源权限由服务端执行；检索、工具、缓存、日志、导出都检查隔离边界。检索到的文档内容不能作为高优先级操作指令。权限不足时明确拒绝相关访问，不让模型决定放行。研究经历可以说明隐私意识，但不要把差分隐私说成所有企业RAG权限问题的解决方案。

### Q11. 企业营销内容Agent怎么从生成走到可用？

设计练习，不是本人已经全部实现：明确受众、平台、品牌与事实约束 → 选取有使用权限的企业材料 → 形成内容计划 → 分平台生成 → 检查事实、品牌表达和平台要求 → 人工确认内容与发布范围 → 受控调用发布工具 → 记录平台回执和版本 → 汇总效果。

发布超时先核对任务和平台回执，不盲目重发；使用任务去重和可追踪状态。原文素材权限与对外发布权限分开考虑。评估同时包含事实和表达质量、人工修改量、采用率、生成时延与成本；业务效果还受流量、受众和投放资源影响，不能简单将点击提升全部归因于生成模型。与Forge对照时明确哪些只有本地导出、哪些是未来设计。

## 4. 必须补齐的基础与手写训练

不是确认题库，而是针对前两次面试暴露的问题安排：

| 优先级 | 主题 | 达标标准 |
|---|---|---|
| P0 | Python完整运行 | 从空文件写出函数、调用、输出和边界验证 |
| P0 | 二分、哈希、双指针、栈队列 | 能说明不变量、终止条件、复杂度，并独立运行 |
| P0 | SQL | JOIN、聚合、窗口函数、Top-N、去重、时间范围、NULL处理 |
| P0 | 并发与异步 | 分清线程、进程、协程、线程池、信号量；说明阻塞与取消 |
| P0 | 项目指标 | 数字可追溯，不混淆精确率和召回率 |
| P1 | 存储 | 事务、索引、缓存和持久化职责、状态一致性 |
| P1 | 工程可靠性 | 超时、重试、幂等、限流、队列、故障恢复 |
| P1 | Java经历相关 | volatile、synchronized、线程池参数与任务执行顺序 |
| P2 | 模型基础 | token、上下文、采样、Embedding、Reranker、RAG与微调边界 |

现场编码固定流程：复述输入输出与边界 → 说明方法 → 写最小可运行版本 → 正常样例 → 边界样例 → 复杂度。不要先纠结输入解析；先询问是否可以固定样例。

SQL练习：给定订单、客户、退款表，统计上月各地区净销售额与排名。必须说明关联粒度，避免一对多连接放大金额；退款归属、时间口径不明确时先澄清。

## 6. 反问面试官：优先选三题

### 技术一面优先

1. 我看了瓴羊的AgentOne，以及分析、营销和客服产品资料，想确认这个岗位主要对应哪条产品线？新同学通常负责模型应用链路、后端平台，还是具体业务功能？
2. 团队当前最难解决的问题更偏业务口径和数据质量，还是Agent规划、工具执行的稳定性？能否举一个可以公开讨论的例子？
3. 一个Agent功能从离线实验到面向客户发布，团队通常要求通过哪些评估？正确率、人工接管、延迟和成本如何权衡？

### 对方确认是问数/报告团队后

4. 我看到小Q教程里有指标公式和“中国区”歧义的调优案例。团队通常怎样沉淀客户业务口径，又怎样避免为每个客户维护大量定制逻辑？
5. 我做过基于事实清单的文章生成。对数据报告场景，团队更难的是取数正确、分析结论可靠，还是报告内容随数据更新保持一致？
6. 自然语言需求有歧义时，产品如何取舍追问次数与直接回答的体验？上线后如何发现用户没有主动反馈的错误答案？

### 工程和成长

7. 对于长时间运行、需要人工确认的任务，团队现在如何组织状态恢复和故障排查？这个岗位会参与这部分吗？
8. 如果入职，前三个月希望我独立交付什么？团队通过哪些代码评审、设计评审和导师机制帮助新人达到要求？

使用方式：先听对方介绍，不重复已回答问题；一题一个核心点，追问其实际难点。避免将“你们是不是用LangGraph”作为主要反问，也不要要求公开内部敏感架构或客户数据。

## 7. 准备节奏

### 若只有一天

- 45分钟：读智能小Q概述、入门案例、小Q报告，画一条问数到报告的流程。
- 90分钟：无AI辅助写基础算法和SQL，必须运行。
- 60分钟：核对简历指标，练三分钟项目说明。
- 60分钟：口述问数Agent设计、并发、故障恢复和权限。
- 30分钟：模拟追问，练先给结论和承认边界；选择三道反问。

### 若有三天

- 第一天：岗位业务资料、项目与实验核查；每日继续基础编码。
- 第二天：RAG、SQL、并发、存储、恢复；用具体场景解释技术取舍。
- 第三天：完整模拟一面，按自我介绍、项目追问、系统设计、现场代码、反问顺序计时。

## 8. 建议阅读顺序

先浏览[AgentOne](https://ai.lydaas.com/)和[Quick Audience](https://www.lydaas.com/quickaudience)了解与内容生成相关的业务，再根据岗位方向选择以下资料，不必一开始只读BI。

1. [智能小Q概述](https://help.aliyun.com/zh/quick-bi/user-guide/smartq)：产品能力地图。
2. [官方入门与调优案例](https://help.aliyun.com/zh/quick-bi/getting-started/smartq-novice-guide)：重点读业务公式与实体歧义。
3. [小Q报告概述](https://help.aliyun.com/zh/quick-bi/user-guide/intelligent-data-reporting/)：联系长文本经历。
4. [报告编辑与引用资源](https://help.aliyun.com/zh/quick-bi/user-guide/document-editing)：理解可追溯性。
5. [报告权限管理](https://help.aliyun.com/zh/quick-bi/user-guide/intelligent-data-reporting-management)：理解企业权限。
6. [百炼知识检索](https://help.aliyun.com/zh/model-studio/rag-knowledge-retrieval)：复习检索链路，仅作为生态技术资料。
7. [LangGraph interrupt](https://reference.langchain.com/python/langgraph/types/interrupt)：复习真实恢复语义。
8. [Python asyncio](https://docs.python.org/3/library/asyncio-task.html)：复习协程、任务和失败行为。
