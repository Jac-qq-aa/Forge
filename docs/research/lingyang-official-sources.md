## 2. Quick BI 值得掌握的真实功能边界

- 智能小Q官方概述列出问数、解读、报告、搭建、洞察等 Agent 功能；可用于理解“取数→分析→成文”的业务链。[功能概述](https://help.aliyun.com/zh/quick-bi/user-guide/smartq)
- 问数操作文档明确有资源权限、数据集选择、缺失时间/指标时反问澄清、业务逻辑 SQL/执行 SQL 展示、Trace_ID、多步规划及多轮对话。这说明可靠性可以落实到产品可见的检查点。[发起问数](https://help.aliyun.com/zh/quick-bi/user-guide/user-guide-for-smart-q-a)
- 小Q报告面向周期报告、经营分析，结合数据获取、分析和可编辑文档。[报告概述](https://help.aliyun.com/zh/quick-bi/user-guide/intelligent-data-reporting)

面试推断：面试官可能关注“答案能生成”和“业务结论可靠”之间的区别。建议演练：用户问销售下降原因时，先澄清指标和周期，再执行受控查询，检查样本与数据质量，区分相关性与因果推断，最后给可追溯结论。这是建议方案，不是断言瓴羊内部实现。

## 4. 建议的反问（按团队回答选择，避免连续盘问）

1. “我看到瓴羊既有 AgentOne，也有分析、营销和客服产品线。这个岗位主要服务哪条业务线？新人最先接触的是通用平台能力，还是具体场景的 Agent？”
2. “团队现在从原型走到稳定交付，最大的困难更偏业务知识与数据质量、Agent 执行可靠性，还是评估体系？方便用一个不涉及保密的场景举例吗？”
3. “我做 Forge 时比较关注事实核验和人工修改。团队如何把离线评估和真实业务效果联系起来？上线前最关键的准入指标是什么？”
4. “如果是多步骤任务，团队目前如何划分自动执行和人工确认的边界？失败后更看重继续执行、回滚，还是交给人工接管？”
5. “面向不同企业客户时，哪些能力会沉淀成公共组件，哪些保留为客户配置？新人会参与怎样的需求分析和抽象过程？”
6. “对于这个岗位，入职前两三个月希望新人交付怎样的具体结果？代码评审、业务学习和导师支持通常如何安排？”

这些问题来自公开产品方向和候选人的项目经历；不预设内部架构、指标、技术栈或组织划分。

## 5. 使用建议

准备主线是企业数据与业务流程中的 Agent 工程能力，而非押注某个框架。优先补现场编码、Python 异步/超时/并发控制、SQL 基础、RAG 误差定位、工具调用和任务状态、评估口径与人工介入。具体深度取决于真实 JD。

与 Forge 的连接可表述为：“我的项目涉及企业材料到多平台内容的生成和修改。看到 AgentOne 营销场景中的内容生产、多平台分发与复盘，我觉得有业务交集。我能带来的是对生成流程和人机修改的实践，也希望在企业级权限、执行可靠性和效果验证方面继续深入。”不要声称本人已实现营销投放、复杂数据分析或生产级多租户能力。
